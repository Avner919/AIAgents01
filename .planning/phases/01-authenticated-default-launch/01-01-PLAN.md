Planning choices, not user-approved contract names: POST /admin/exchanges; optional JSON property exchangeProcessFileName, bound by LaunchRequest.ExchangeProcessFileName; 200 JSON with processId and defaults containing clientFileName, clientExecutablePath, clientWorkingDirectory, inputDirectory, outputDirectory, timeoutMilliseconds. No request body, JSON null, empty object, omitted property, null, empty, and whitespace property select defaults. Nonblank input returns 400 code unsupported_client_override because explicit client selection belongs to Phase 2.

AdminApi:ApiKey and AdminApi:UtilityPath are separate API options. ApiApplication.Build(string[] args, Action&lt;WebApplicationBuilder&gt;? customize = null) registers production services, invokes customize before building, and returns WebApplication. Production Program awaits RunAsync. Test customization uses per-host configuration, loopback port zero and injected dependencies, with no global environment/cwd mutation.

ExchangeConfigurationLoader.Load(string utilityDirectory, IReadOnlyDictionary&lt;string, string?&gt; environment) returns fresh ExchangeOptions. ExchangeConfigurationLoader.CaptureEnvironment() captures the current inherited dictionary. ExchangeProcess.ResolveDefaults(ExchangeOptions options, string utilityDirectory) returns immutable ResolvedExchangeSettings. UtilityLaunchPreparation.Prepare() captures settings and returns UtilityLaunchSnapshot. IUtilityProcessLauncher.Start(UtilityLaunchSnapshot snapshot) returns int PID. API response projection never serializes options, snapshots, or credential-bearing types.

ExchangeProcess.BuildClientStartInfo(ResolvedExchangeSettings settings) returns a pure System.Diagnostics.ProcessStartInfo: FileName is the resolved client executable, WorkingDirectory is the resolved client directory, UseShellExecute=false, and ArgumentList contains exactly login, password, resolved input directory and resolved output directory in that order. It leaves the Arguments string empty. Existing StartClient uses this exact builder; no request-side explicit client selection is introduced.

UtilityLaunchSnapshot is a sealed immutable class, colocated with UtilityProcessLauncher, containing UtilityPath, UtilityDirectory, resolved settings and a defensive read-only environment copy. Avoid generated value-printing methods on internal types that contain credentials. ResolvedExchangeSettings has the six safe fields plus internally accessible credentials needed by the existing console client contract; consumers project safe fields explicitly.
</interfaces>

## Trust Boundaries

| Boundary | Description |
|---|---|
| Caller to admin HTTP route | Untrusted header/body must pass real authentication before disclosure or process creation |
| Utility deployment/configuration to shared resolver | Operator files and inherited environment become immutable execution settings |
| API to Windows process creation | Only the operator-configured utility target and cwd cross the process boundary |
| Internal settings to public JSON/logs | Credential-bearing internal data must not cross the six-field projection boundary |
